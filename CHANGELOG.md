# Changelog of the libretro core

What changed in the libretro core of this fork, newest first. Changes that come with a merge of upstream lindbergh-loader are in upstream's own history (`docs/changelog`).

## Unreleased

- The core is linuxloader, after the project it is built on, which is to run other arcade systems than Lindbergh too: `linuxloader_libretro.so` / `.dll` and `.info`, shown as Sega - Lindbergh (linuxloader). It reports its version as the loader's release and this fork's commit, as `v3.0.13 (libretro core 911049d)`, and logs it at load. The loader now goes to `system/linuxloader/`, and RetroArch keeps the core's saves and options under linuxloader: move `saves/Lindbergh/` (the games' EEPROM and SRAM) to `saves/linuxloader/`, and `system/lindbergh/` can be deleted (NNshi).
- Debug > EMULATE_DRIVEBOARD's Default (per game) emulates the drive board for Initial D 4 and 5 and Hummer too, not only OutRun 2 SP, so they rumble as well (NNshi).
- RetroArch's Reset starts the game again, as at load; it did nothing (NNshi).
- Resolution's tooltip warns that a resolution above the display's breaks some games or keeps them from starting (NNshi).
- Virtua Fighter 5 at Resolution 3840x2160 or 5120x2880 runs at 2880x1620, the most it renders, instead of a black screen (NNshi).
- Virtua Tennis 3: Button 3, which the game does not read, is Lob (Button 1 and 2 together). RetroArch's controls list names the button games' buttons: Punch, Kick, Guard in Virtua Fighter 5, Top Spin, Slice, Lob in Virtua Tennis 3 (NNshi).
- Player 2 plays the button games (Virtua Fighter 5, Virtua Tennis 3) on port 2's pad with the same buttons and directions as player 1; before, only Start worked there (NNshi).
- RetroArch's controls list names the buttons and sticks by what they do in the game (Gas, Brake, Gear Up, View Change, Missile, Trigger, Reload...), taken from the loader's bindings, and with Gun Aim on Analog Stick from the gun games' layouts; nothing is bound differently, and RetroArch's remapping now has something to rebind (NNshi).
- The core takes programs without an extension and `.exe` (Primeval Hunt's `game.exe`) as content; with RetroArch's Filter Unknown Extensions off, the file browser offers them (NNshi).
- New option Debug > ABURNER_MOTION_OFF, last, on by default: After Burner Climax's motion set to off in its EEPROM at start, as its test menu does, without which it does not start on the Deluxe cabinet it is set to out of the box; from the second start, as the game writes its EEPROM at its first. Rev. B (DVP-0009B) does not start, from either layout (NNshi).
- After Burner Climax from its dump as it is, `abc` and `game` on `disk0`: the `rom` and `shader` folders the game opens from the folder above its program are looked for on `disk1` beside it, where the dumps hold them (NNshi).
- New option Debug > TEST_MODE (Off by default): On starts the content in test mode, as the loader's `-t` (or the game's separate test program); leaving the test menu starts the game (NNshi).
- The House of the Dead 4 from its dump's `hod4data` also gets its shaders patched (the shader cache read them from `fs` only, so the game quit), and a file the game looks for and misses is named in the loader's log, for a dump laid out otherwise (NNshi).
- Dumps as they are: The House of the Dead 4's `hod4data` folder needs no renaming to `fs`, and After Burner Climax's `abc` and `game` folders no moving from `disk0` to `disk1`; a file the game does not find where the loader's layout has it is looked for in the dump's own folder (NNshi).
- Options reshuffled: Free Play is Debug > FREEPLAY (Default leaves the game's own, Off, On), Debug's KEEP_ASPECT_RATIO is Video > Force 16:9 (Disabled by default; Enabled makes every game widescreen, as KEEP_ASPECT_RATIO 0), and the System category is gone (NNshi).
- Test as on a cabinet: Test (R3 or T) during play opens the test menu. A game that quits for it within 5 s (Rambo, Virtua Fighter 5, After Burner Climax) is started again in test mode with the loader's `-t`, a game with a separate test program as that program, with or without `.elf`, ended by the core after 5 s if it does not quit: OutRun 2 SP SDX's JenTest (in a JenTest folder beside Jennifer's), Virtua Tennis 3's vt3_testmode, The House of the Dead 4's hod4testM, The House of the Dead EX's hodextestR, Apache's apachetestM. A game that keeps running has its menu in the game (Initial D). Leaving test mode starts the game again, as does a game that quits by itself after its first 10 s. Test held from the test menu does not reach the game started again until let go. The Test Mode (Restart) option is gone. New option Input > Service and Test Buttons (on by default): off, L3 and R3 are not Service and Test, so they are not pressed by accident (NNshi).
- RetroArch's pause holds the game still: once the core has not run for longer than a frame takes, the game's wall clock (`gettimeofday`, `time`, `clock_gettime(CLOCK_REALTIME)`) stops and its sound is not handed on, so Initial D 4 no longer jumps ahead by the paused time and Too Spicy's sound no longer plays on (NNshi).
- Debug: KEEP_ASPECT_RATIO (Default On), which since the upstream merge also makes After Burner Climax and Ghost Squad Evolution render 4:3, as their cabinets were; Off gives widescreen back (NNshi).
- No sound in any game since the new HUMMER_FLICKER_FIX and PRIMEVAL_HUNT_SCREEN_MODE defaults: setting them asked the loader too early whether it runs for the core, which on Windows hooks SDL's audio before MinHook was set up, so the hook was never made (NNshi).
- Primeval Hunt's sound: it plays through ALSA (the loader's alsa2sdl), not FAudio, and its SDL device had no post-mix hook, so nothing reached the core. Only Primeval Hunt's ALSA device goes to the core: OutRun 2, Virtua Tennis 3 and Virtua Fighter 5 open ALSA beside FAudio and went silent with theirs too (NNshi).
- New defaults: Audio Thread on, so the sound keeps its pace where a game drops frames (OutRun 2 SP's announcer is lost with it); and in the loader, without a `linuxloader.ini` setting of their own, HUMMER_FLICKER_FIX on (Hummer's flicker on NVIDIA; other drivers ignore what it turns off) and PRIMEVAL_HUNT_SCREEN_MODE 1, Primeval Hunt without the touch screen beside the picture (NNshi).
- New core option category Debug, last: the `linuxloader.ini` settings the core does not otherwise cover (EMULATE_DRIVEBOARD and the other boards, REGION, LINDBERGH_COLOUR, DEBUG_MSGS, USE_ALT_JVS_PASSTHROUGH, BOOST_RENDER_RES, the Graphics and GameSpecific switches, ID_CARDFILE_AUTOLOAD, the crosshair switches, ENABLE_NETWORK_PATCHES), each with Default first, which leaves the game's own value or the `linuxloader.ini`'s; a value set goes over the file's at the next start. Paths and cabinet IP addresses stay in `linuxloader.ini` (NNshi).
- Merged upstream Linux Loader up to 4ffa095 (28.10.2026: graphics bridging, shader handling, audio, touch screen, pinned Mesa); its changes are in upstream's `docs/changelog` (NNshi).
- README: Game folders, what After Burner Climax's and The House of the Dead 4's dumps need moved or renamed before they run, and NVIDIA's anisotropic filtering for the loader on Windows (NNshi).
- Gun games for two players: new Input options Gun Aim, Analog Stick (default: each player's left stick or D-pad moves the aim, R2 fires, R reloads, L2 is the gun's button) or Mouse (RetroArch's light gun on each player's port, which follows the mouse: left fires, right reloads, middle is the gun's button, off the picture reloads), Gun Pointer Sensitivity (50 to 200%, the sticks' speed, the same across as up and down) and Crosshair, the core drawing player 1's blue and player 2's red over the picture. Per game: Too Spicy's pedals on L and R with reload on L2, in its test program too; Ghost Squad Evolution's Action and Change on L2 and L, with the mouse on the right and middle buttons; Primeval Hunt aimed like the others, its pump on L2 or the mouse's middle, its touch screen on the mouse's clicks; The House of the Dead 4's shake on L or the mouse's middle, its gun button on the mouse's right; Too Spicy's pedals on the mouse's middle and right, as the arrows are RetroArch's D-pad; Let's Go Jungle's aim the right way round. The loader takes both players' guns straight from the core instead of player 1's as a mouse; the touch screen games take RetroArch's light gun or, while touched, its pointer, without the former Pointer option (NNshi).
- A game's EEPROM and SRAM are kept in RetroArch's saves directory for the core (`saves/Lindbergh/` with saves sorted by core), named by the game's DVP (`DVP-0015.eeprom.bin`, `DVP-0015.sram.bin`), not in the folder of the ELF that runs: a game's test program and the game share them, so what OutRun 2 SP's JenTest sets reaches Jennifer. The `eeprom.bin` and `sram.bin` in the game's folder are copied there the first time; paths the `linuxloader.ini` sets stay as they are (NNshi).
- Core options in categories (Video, Input, Audio, System) with tooltips (core options v2); Steering Inner Zone and Steering Effect show and hide as Steering Response changes, without reopening the menu, and Inner Zone lists 5 to 50 in order (25 still the default). New option Input > Force Feedback to Rumble, on by default, its tooltip naming the games it works with (NNshi).
- Builds: packages come from Ubuntu's own archive instead of Azure's mirror, which served some 50 KB/s, and the Windows job installs only MinGW, without upgrading the whole runner; a package fetch that stalls retries and then fails its step instead of holding the job for its whole time (NNshi).
- Windows: at a resolution larger than the screen, the game draws into a framebuffer of the core's own at the full resolution, not into the hidden window's, which the driver cuts to the screen's size: at 2160p and 2880p on a 1440p monitor only a corner of the picture came through. Up to the screen's size it draws to the window as before, since OutRun 2 SP lost textures on the core's framebuffer (NNshi).
- Audio: the loader mixes by the clock. SDL's dummy device, which hands the mix to the core, waited a block's length in whole milliseconds (5 ms for 5.33), so it mixed some 6 % fast and the core cut the backlog every second or two; streamed music skipped, short effects hid it (NNshi).
- New option Steering Response: linear (as before) or logarithmic, the left stick's X on the curve of the Sega System 32 racers' dip switch, less of the turn around the centre and steeper towards the ends, so a stick steers less twitchily. With it, Steering Inner Zone (5 to 50%, 25 by default) sets the share of the turn at the centre and Steering Effect the outer part, Cubic (strong, the default) or Square (weak); both are shown only with logarithmic (NNshi).
- New option Free Play (Restart): default (the game's own setting), enabled or disabled, set in the game's EEPROM at start as linuxloader.ini's FREEPLAY does (NNshi).
- Force feedback: the drive board's, which the loader turns into left and right rumble, reaches RetroArch's rumble on player 1's pad; the core's pads have no haptics of their own for SDL (NNshi).
- The Windows build's artifact holds `lindbergh_libretro.dll` and `lindbergh_libretro.info` side by side, with no folders, no zip inside and no `system/` (NNshi).
- New option Audio Thread (Restart), off by default: the sound goes to RetroArch's audio thread (SET_AUDIO_CALLBACK) as the loader mixes it, by the loader's clock as in the loader alone, so it keeps its pace where a game drops frames, as Initial D 4's car select at 40 fps; OutRun 2 SP's announcer is lost with it (NNshi). Where RetroArch has no audio thread to give (recording), a frame's worth each run as with it off.
- The core carries the loader and writes it to `system/lindbergh/` at load when what is there is from another build or missing, so the core is the one file to install (NNshi). Its zip is made by the build (miniz, MIT, in `src/libretro/miniz/` reads it).
- The pads' triggers (L2 and R2, gas and brake in the driving games) reach the game: the core's pads sent them from 0 at rest, where SDL reads a trigger from -32768 at rest as a pad's driver reports it, so they sat half held and the games took no gas or brake (NNshi, OutRun 2 SP, Initial D 4).
- The players are the core's pads, RetroArch's ports 1 and 2, and nothing else: on Windows the loader also saw the machine's own controllers and gave them P1 and P2 ahead of the core's, bypassing RetroArch's mapping (NNshi).
- Sticks have no dead zone of the loader's own, RetroArch's analog dead zone applies: the loader's 8000 jumped from the centre straight to a quarter turn, which steered as a dead zone and then too sharply. A `controls.ini` can still set one (NNshi).
- Without a `linuxloader.ini` the loader no longer logs a garbled file name on Windows; it read an uninitialised path and used the defaults anyway.
- New option Resolution (Restart): native (linuxloader.ini's), 1280x720, 1920x1080, 2560x1440, 3840x2160 or 5120x2880, the width and height the games the loader can patch render at; frames up to 5120x2880 (NNshi).
- Audio: one frame's worth each run out of a small cushion, and SDL in the loader mixes in smaller blocks: the sound was scratchy, with underruns (NNshi).
- Input: the core's pads are there before the loader looks for controllers, and SDL takes their input although the game's window stays hidden; without a `controls.ini` Start is start, Select a coin, L3 service and R3 test, and RetroArch's keyboard reaches the game (NNshi).
- Windows: the core starts `linuxloader.exe`, which loads the game's ELF itself; shared memory through a named file mapping and events, the audio through a hook on SDL's stream.
- The libretro core: the game runs in the loader as a process of its own, with frames, audio and input exchanged through shared memory; Linux x86-64, Linux aarch64 through box64.
